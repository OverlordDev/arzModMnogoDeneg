# ARZ Terminal — визуальный каркас

Минималистичный прототип системы фарма, перекупа и аналитики рынка Arizona RP.

## Как открыть

Вариант 1 — просто открыть `index.html` в браузере.

Вариант 2 — локальный сервер (удобнее для проверки на телефоне):

```powershell
cd C:\Users\negrozoido\Desktop\arzModMnogoDeneg\arz-terminal
python -m http.server 8080
```

Открыть: `http://localhost:8080/`

Вариант 3 — Node-сервер (для VPS, ноль зависимостей):

```bash
node server.js          # PORT=3000 по умолчанию
```

Проверка: `http://localhost:3000/api/health` → `{"ok":true,...}`.
Деплой на VPS для двоих — см. `deploy/DEPLOY-VPS.md`
(systemd-сервис, `deploy/vps-setup.sh`).

Для мобильного вида: `http://localhost:8080/preview-mobile.html` — страница с iframe 390×844.

## Графики

Все графики цены (карточка предмета, History, капитал игрока) — один компонент
`js/charts.js`: наведи курсор (или проведи пальцем, или фокус + стрелки) — появится
перекрестие и подсказка с датой/временем и значением каждой линии. Для дневных цен
предмета в `data/market_*.json` у каждой точки есть дата (`historyDates`, их добавляет
`scripts/import_arzmarket.py`); без неё график подписывает точки номерами.

## Игрок из игры (локально)

Инвентарь, деньги, сытость и розыск читаются из самой игры. Arizona присылает
их клиенту CEF-событиями (пакет 220), скрипт MoonLoader их **только читает**:

1. `game/arz_export.lua` → в `<Arizona>\bin\arizona\moonloader\`. Пишет только
   белый список событий в `arz_player_events.log` (авторизация и токены не пишутся).
   Ничего не отправляет серверу и в сеть, пакеты не перехватывает.
2. Зайти на сервер: полный инвентарь приходит **один раз при входе**, дальше —
   изменения слотов. Без этой загрузки сайт помечает инвентарь «неполно».
3. `node server.js` на этом же ПК: сервер следит за файлом и толкает изменения
   в браузер по SSE (`/api/player/stream`, ~0,15 с), запасной опрос — `/api/player`.

Стоимость — по ценам ArzMarket (`data/market_*.json`): скупка / продажа / середина.
Предметы без рыночной цены в сумму не входят и перечисляются отдельно.
ID предметов → названия: `data/items_names.json` (из репо ArzMarket).

**Игровые цены Центрального рынка.** Экспортёр заодно читает окно «Средняя цена товаров
при продаже» (средняя цена за 30 дней, официальные цифры игры) и пишет только его в
`arz_market_dialogs.log` (разбор — `game/arz_gameprices.js`). Одна страница вмещает 40
предметов, дальше нужно **листать вручную** («Следующая страница»; скрипт сам ничего не
нажимает) — страницы накапливаются, поздние перекрывают ранние. На сайте это колонка
«Игра 30д» в инвентаре: цена **не подменяет** ArzMarket, а сверяется с ним (жёлтый ×N —
расхождение в 3+ раза) и служит запасной
оценкой для предметов, которых нет в ArzMarket (бейдж «игра»; в «скупку»/«продажу» такие
не входят). Для Yuma медианное отношение игра/ArzMarket ≈ 0,95. Валюты не смешиваются:
`:CASH:` = SA$ (Yuma), `:CASHV:` = VC$.

**История предмета и автообход.** Если в списке выбрать предмет, игра показывает окно
«Продажа товара 'X' за последние 30 дней»: по каждому дню число продаж и среднюю цену.
Экспортёр записывает и его; по нему считается цена за 7 дней (она точнее 30-дневной),
продажи за неделю (ликвидность) и тренд — всё видно подсказкой в колонке «Игра».
Чтобы не открывать каждый предмет руками, есть **опциональный** `game/arz_scan.lua`:
`/arzscan`, затем открыть окно «Средняя цена товаров при продаже» — скрипт сам открывает
предмет → историю → «Назад» → следующий предмет → «Следующая страница» … до конца списка.
Это **не только чтение**: он отправляет серверу те же ответы на диалог, что и твой клик
(паузы 0,4–0,8 с, `/arzscan fast` — 0,25–0,5 с, `/arzscan 300` — своя пауза 300–480 мс (150…5000); любое неожиданное окно / несовпадение названия / таймаут = СТОП,
`/arzscan stop` — вручную, потолок 8000 нажатий (весь список ~2300 предметов — около 5000)). Правила сервера могут запрещать
автоматизацию — риск на владельце аккаунта. Логика проверена на имитации сервера
(страницы по 40, возврат на первую страницу, конец списка, чужое окно, ошибка индекса),
но в живой игре ещё не запускалась: первый запуск смотри глазами.

**Банк и депозит.** Экспортёр пишет и события банка (`event.bank.updateDepositData`, `updateMainData`):
депозит, лимит дохода, доход за PayDay, уровень, комиссия снятия, купленные счета (`game/arz_bank.js`).
Они приходят **только когда в игре открыто окно банка**, поэтому на сайте это «данные на момент последнего
открытия». Деньги на депозите сверх лимита дохода **не приносят** — карточка «Банк и депозит» показывает,
сколько работает и сколько простаивает, сколько упускается за PayDay и что даёт следующий уровень; «Капитал»
дополнительно показан с банком и депозитом (`netWorth`). История капитала по-прежнему считается без банка.

Приватность: `/api/player*` отдаются только с loopback-адреса и Host `localhost`,
без CORS (иначе любая открытая вкладка могла бы прочитать инвентарь). На VPS/статике
данных игрока нет намеренно. Файл игрока: `ARZ_EVENTS_FILE`, интервал
страховочного разбора: `ARZ_PLAYER_PARSE_MS` (по умолчанию 30000).

**Заработок в час** считается по изменениям денег (`game/arz_stats.js`): приход,
расход и чистыми за 15 минут / час / сессию. Приход — любые поступления, а не
только работа; если в окне доминирует одно крупное поступление, оно помечается
«разово». **История капитала** (деньги + оценка инвентаря) пишется раз в минуту при
изменениях в `local/player_history.jsonl` — это личные данные, папка в `.gitignore`
и не должна оказываться в `data/` (её автоматически пушит планировщик).
Тесты: `npm test` (синтетические данные, реальные логи в репо не кладём).

**Автозапуск сервера с Windows**: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_autostart.ps1`
кладёт ярлык в «Автозагрузку» (без прав администратора): сервер стартует при входе в систему
скрытым окном, перезапускается после падения (`scripts/run_server.bat`), лог — `local/server.log`.
`-Status` — состояние, `-Stop` — остановить, `-Uninstall` — убрать автозапуск и остановить.

**Сохранение в Firebase (по желанию)**: снимок игрока и история капитала могут
писаться в Firestore (REST, без SDK, анонимный вход). Включается, если есть
`local/firebase.json`; настройка проекта, правила и **схема данных для мобильного
приложения** — `deploy/FIREBASE.md` (вход по e-mail/паролю даёт приложению тот же `uid`).
Неполный инвентарь в облако не пишется; статус и причина ошибок видны в Player.

`game/arz_recon.lua` — разведчик (логирует имена CEF-событий, чтобы находить новые),
`game/arz_parser.js` — события → состояние, `game/arz_value.js` — оценка и советы.

## Телефон (веб-приложение с ПК, без хостинга)

Сайт на телефоне — **тот же сайт**, который раздаёт `node server.js` на твоём ПК: открываешь адрес ПК в браузере
телефона (можно «Добавить на главный экран»). Никакого хостинга и облака не нужно, всё работает вживую (те же
SSE-обновления, что и на ПК).

1. **ПК:** раздел **Player → блок «Телефон»** — там ссылки вида `http://192.168.x.x:3000/?key=…` (домашняя сеть)
   и, если стоит Tailscale, `http://100.x.y.z:3000/?key=…` (откуда угодно). Отправь ссылку себе (Telegram «Избранное»)
   и открой на телефоне: ключ сохранится в cookie, из адреса он сразу убирается, ссылка больше не нужна.
2. **Брандмауэр Windows:** если телефон не открывает ссылку — один раз запусти
   `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/allow_firewall.ps1` (спросит права администратора;
   открывает порт только для частных сетей и для адресов Tailscale).
3. **Вне дома:** поставь бесплатный [Tailscale](https://tailscale.com) на ПК и телефон — это VPN между твоими
   устройствами (канал шифруется, порт в интернет не открывается). ПК при этом должен быть включён.

**Доступ и безопасность.** Данные игрока (`/api/player`, поток) вне самого ПК отдаются **только с ключом**: 24 случайных
байта в `local/access.json` (в `.gitignore`), по ссылке с ключом браузер получает HttpOnly-cookie. «Сменить ключ» (кнопка
в блоке «Телефон») разлогинивает все телефоны. Ключ не пишется в `server.log`. Честно: по обычному HTTP внутри Wi-Fi
cookie теоретически подсматривается в той же сети, через Tailscale канал шифруется; открывать порт в публичный интернет
не нужно и не стоит. Статика (`server.js`) отдаёт только `index.html`, `styles.css`, `js/`, `data/`, `icons/`,
`manifest.webmanifest`, `sw.js` — раньше отдавалось всё из папки проекта (включая `local/` с токеном облака).
`HOST=127.0.0.1` ограничивает сервер этим ПК.

**Приложение (PWA).** Манифест, иконки и service worker есть; установка/офлайн работают только по HTTPS (например,
через `tailscale serve`), по обычному `http://` сайт просто открывается в браузере. Раздел Player на узком экране
сжимается: скрыты второстепенные колонки, суммы в «млн», страница не прокручивается вбок ни в одном разделе.

**Облако (необязательно).** `server.js` по-прежнему умеет складывать данные в Firestore (зеркало `web/latest`, каталог
игровых цен, история банка) — это задел под будущее нативное приложение (`deploy/FIREBASE.md`). Для телефона оно не нужно.

## Скуп (раздел «Скуп», `/api/flip`)

Что ставить на скупку в лавке на ЦР, чтобы перепродать с прибылью. Считает `game/arz_flip.js` по ценам скупки и продажи лавок
(ArzMarket) и игровым ценам ЦР (медиана сделок за 7 дней):

- **Скуп по** = цена скупки лавок + 1%; **Продать по** = меньшая из «лавки просят» и «реально проходит в игре»; прибыль = продажа × (1 − комиссия) − скуп.
- Размер лота — не больше 25% бюджета и не больше того, что разойдётся за 3 дня при 10% оборота (оборот берём не выше игровых сделок).
- Связки с прибылью выше 60% отбрасываются как мусор в данных (скупка по 11$ при продаже за 15 000$ и т. п.); падающая, скачущая цена и завышенные «просят» режут рейтинг.
- Параметры API: `budget`, `comm` (%), `roi` (%), `q`, `cat`, `server`. Бюджет, комиссия и категория запоминаются в браузере.
- Ограничения: заявки конкурентов в реальном времени не видны, комиссия ЦР по умолчанию 2% (ADD VIP; без него впиши свою), цены ArzMarket бывают на несколько дней старше; цифры «в сутки» — верхняя оценка.
  Тесты: `node game/test_flip.js`.

## Реальные данные (ArzMarket)

Market, связки на Dashboard/Arbitrage и карточка предмета уже умеют
подтягивать **реальные средние цены лавок**:

- источник — публичные агрегаты скрипта Arizona Market
  (`github.com/FREYM1337/forumnick`, папка `avg_price`, файлы
  `info_users_buy_<server>.json` / `info_users_sell_<server>.json`);
- `buy` = скупка (что лавки платят), `sell` = продажа (что просят);
- обновление: `python scripts/import_arzmarket.py --server yuma vc`;
- готовые файлы лежат в `data/` (`market_yuma.json` — 2 376 позиций,
  `market_vc.json` — 3 396 позиций, свежесть — 16.11.2026);
- **серверы: только Yuma и Vice City**, экономики изолированы
  (межсерверного арбитража нет: у Yuma — $, у Vice City — VC$);
- загрузчик — `js/realmarket.js`: подменяет мок-данные, строит
  внутрисерверные связки (с фильтрами от мусора:
  объём с нужной стороны ≥ 30, стабильность цен, одинаковый порядок цен);
- **история цен**: только сохранённые дампы в `data/history/<server>/`
  (автоматика удалена, новые не копятся);
  раздел **History** в терминале строит по ним графики
  скупки/продажи любого предмета.
- если файла сервера нет — остаются демо-данные, в Market видно
  «Сервер данных».

Подробности и ограничения — в `data/README.md`.
